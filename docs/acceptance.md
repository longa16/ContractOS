# Test plan and acceptance

## Automated suites

`npm test` executes PostgreSQL/PGlite policies and RPCs plus domain/AI/file/network rules. It can fail on broken MFA, RLS, composite tenant constraints, missing evidence, stale revisions, duplicate records, unauthorized writes, invalid quoting, expiry and approval binding. No zero-test run is considered validation.

`npm run test:browser` requires the local Supabase stack, `.env.local` generated by `local:setup`, Docker and Chromium (`CHROMIUM_PATH` if different). It refuses a remote Supabase hostname. Temporary confirmed users/organization are created and cleaned up in their own scope. It exercises real Auth/TOTP, forms, cookie protection, XSS escaping, submission blocking and private Storage isolation. Screenshots, traces and video are disabled to avoid recording setup secrets.

`npm run typecheck`, `npm run build`, and `npm audit --audit-level=moderate` check compilation and known dependency advisories. An audit with no findings is not proof that the application has no vulnerabilities.

## User acceptance on staging

- [ ] Confirm an owner email, provision membership and enroll TOTP. An `aal1` owner session cannot read internal data or mutate through REST/RPC.
- [ ] Confirm a VA, enroll TOTP, add a market/requirement, and verify that approvals, qualification and evidence verification are denied.
- [ ] Ingest the same SAM notice twice without duplicate opportunities. Change material source input and observe approval invalidation. Test window/pagination limits.
- [ ] Manually import a Maryland solicitation with an authoritative HTTPS source and deadline.
- [ ] Explicitly authorize AI screening of public source text, inspect structured draft and unknown/risk factors. Verify no automatic bid decision.
- [ ] Upload a public text PDF; explicitly authorize extraction. Inspect each exact excerpt/page, mandatory flag and risk. Scanned/oversized/malformed documents fail closed and use a separately reviewed OCR path.
- [ ] Confirm a contractor email and consume its matching invitation. Reject wrong-email, expired and reused invitations; no internal role is granted.
- [ ] Upload W-9, insurance, license and quote. Require object existence and expiration metadata where applicable before owner verification.
- [ ] Another contractor cannot read rows or download private files; contractor cannot verify its own evidence, change roles, overwrite or delete approved files.
- [ ] Inspect matching reasons; manually verify geography, license applicability, insurance, bonding, capacity, availability, workers' compensation and past performance for this market.
- [ ] Approve pursuit, enter verified quote, price units/costs/markup, and compare integer-cent arithmetic to expected totals. No unapproved pricing can generate a draft.
- [ ] Verify company facts with supporting references. Generate JSON draft; confirm all claims trace to fact IDs and all requirement responses to source/page/evidence. Complete missing sections/forms in a reviewed package.
- [ ] Review every mandatory requirement. Record opportunity-specific subcontracting/set-aside, contractor and pricing approvals. Upload/inspect the final PDF after the latest business revision.
- [ ] Block submission for deadline passed, missing/expired/revoked evidence, unreviewed amendments, stale quotes/price/proposal/package, missing human gates.
- [ ] Add an amendment: mandatory requirements reopen and downstream approvals become stale. Reconcile superseded information and reapprove a current revision.
- [ ] Replace the final PDF: the previous package approval is unusable. Explicitly revoke approvals and verify submission blocking.
- [ ] Approve the complete current package; manually submit to the official portal; record the real receipt. Attempt edits to the closed dossier and confirm rejection.
- [ ] Inspect append-only audit, verify no credential/document content leaks, validate hosted TLS/storage encryption/backups and an actual restore.

## Shared catalog acceptance

Automated PostgreSQL coverage checks global deduplication, no-MFA/contractor access denial, client write denial, cross-organization selection/refresh denial, two independent private selections, isolated saved filters, no publication of private notes, and submission blockers on changed source revisions. The browser owner flow covers saved filters, selection into a private dossier and explicit refresh after a synthetic source change, using the real local Supabase services. Live SAM/provider coverage remains pending real credentials.
